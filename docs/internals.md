# Internals

The package is a dual-target plain-Node ESM implementation of the durable v0.4 binary-automation contract with bounded v0.2/v0.3 migration and read-only protocol compatibility:

```text
future host activity -> observe -> correlate -> recommend -> explicit action
```

Automatic recommendations On/Off controls only the automatic path. It never grants a skill-file write. The v0.1 manual analyzer, `durableAutonomy: false`, Manual/on-demand scan, project modes, ordinary Pause, separate passive-call consent, and legacy session registry are absent from the v0.4 runtime and package.

## Dual Targets

- `self-evolve.js` is the headless-safe server entry exported at `.` and `./server`. It default-exports only `SelfEvolvePlugin`, imports no TUI target or `@opentui/*` runtime, owns durable state/effects, and returns exactly one lifecycle `event` hook.
- `self-evolve-tui.tsx` is the typechecked authoring source. The repository-owned build emits byte-stable `self-evolve-tui.generated.js`, the public native target exported at `./tui`. Host OpenTUI/Solid modules remain external.
- `self-evolve-tui.js` owns target-only host registration/lifecycle wiring. `self-evolve-tui-store.js` owns the project-scoped reactive projection consumer. Neither is reachable from the package root.
- Shared helpers import from neither package target.

The package checker enforces exact files, single default export, dual-target isolation, private/runtime-file exclusion, deterministic generated bytes, optional-peer ranges, dependency audit, and a fresh peerless root consumer. Separate packed-TUI and coexistence gates prove the target-specific host lanes.

8. `self-evolve-synthesis.js` owns only the durable hidden deny-all-tools synthesizer and critic sessions; it retains exact provider-bound target bytes.
9. `self-evolve-applier.js` is the sole transactional skill writer and rollback owner.

## Host-Global Discovery Adapter

OpenCode 1.18.x does not attach a trustworthy source-kind tag to each stable resolved `/skill` item. The adapter therefore composes three official exact-origin projections:

1. `/path` (or the typed `client.path.get()` subset) for official home/config/project/worktree paths;
2. directory-scoped `/config` (or `client.config.get`) at the host config directory for the global-only local `skills.paths` view;
3. directory-scoped `/skill` for both the host config directory and acting project.

Only canonical local global entries present in the global-only host projection are eligible. Standard config, global `.agents`/`.claude`, and global-only configured local paths are classified before filesystem access. Project-contained, project-only, URL, embedded, built-in, cache, ambiguous, malformed, noncanonical, symlinked, unsafe, nested-ambiguous, or drifted entries fail closed. Host/config/location/content disagreement produces bounded diagnostics and no target.

The adapter emits immutable source and skill receipts containing only the official origin/path identities, normalized source/preference generations, canonical logical name/path, and exact content size/hash. Discovery is read-only, may run for catalog inspection while automation is Off, and never changes preferences, permissions, policy, recommendations, or files.

## Boot, Preference, And Epochs

The factory returns a stable hook shape before bounded host/root validation finishes. Before validated boot, the lifecycle hook has no integration and no durable authority. After boot, every admitted lifecycle event freshly reads:

- `automaticRecommendationsEnabled`;
- the three required data permissions;
- the exact automation generation;
- project Include/Exclude;
- Emergency Stop, breaker, budget/quiet, host, and corruption state.

Off, a missing permission, a generation problem, or an operational suppressor returns before source-lineage hydration, session/message reads, provider calls, durable observation/contribution/candidate writes, or scheduler admission. Passive `chat.message` is never installed.

Turning On atomically enables the permission bundle and advances the automation epoch once. Turning Off advances it once without purging. Permission revocation atomically writes the false bit, Off, epoch advance, cleanup/invalidation intent, and audit; restoration leaves Off. Transition IDs/nonces make retry idempotent and stale/conflicting requests fail.

The terminal-root epoch remains accepted-terminal purge/reinitialize truth. The breaker epoch remains failure-trip/reset truth. The automation epoch is reversible ordinary preference truth. Every authoritative mutation-lock acquisition refreshes the relevant epochs; cached permissive state never proves authority.

Fresh and valid legacy migration initialize On/all-required-permissions exactly once while preserving project exclusion and Emergency Stop. A valid v0.4 state prevents replay. Malformed/corrupt/unsupported authority opens Off.

## Generation-Fenced Automatic Pipeline

Every automatic boundary binds and freshly compares the automation generation: event admission, session/message read, receipt/observation persistence, capsule/contribution publication, candidate materialization, lease/reservation, synthesizer dispatch, critic dispatch/completion, recommendation persistence, scheduler continuation, and settlement.

Off closes old-generation authority before admitting new work. Process-local AbortControllers reduce latency but are not authority. Recovery supersedes only collecting, eligible, synthesis-pending candidates and admitted/dispatched attempts from the old generation; published recommendations and terminal no-change/failed-closed/recommended outcomes remain. Late provider output cannot create new durable authority.

Re-enable first establishes a durable source-cursor boundary. Messages/events accumulated while Off and pre-Off observations, contributions, or support cannot rematerialize a candidate in a new generation. Only future post-On activity counts. Candidate draining remains bounded, budget-aware, ordered, restart-safe, and breaker-aware.

The synthesizer and critic remain hidden deterministic deny-all-tools sessions. `session.delete` is mandatory. Each prompt uses the exact no-follow descriptor-bound existing-skill bytes whose hash was proven; no second path read occurs after proof. New-skill synthesis binds the explicit creation root before provider use.

## Explicit Actions And Filesystem Effects

Projection and server authority are split into `canApply`, `canReject`, and `canUndo`.

- Apply requires a fresh operator edge and current recommendation, support, required permissions, host target or creation-root provenance, content, critic, deterministic, nonce/version/grant, lease, path/hash, Emergency Stop, breaker, and integrity proofs.
- Reject is file-free and remains available while Off or after privacy revocation.
- Exact Undo requires snapshot/current-applied-hash/path/transaction/grant/lease integrity and remains available while Off, after privacy/support revocation, Emergency Stop, or breaker trip.

Automatic recommendations state is never a write grant. Ordinary Off is not an action suppressor. Restoring a permission may restore Apply while automation remains Off and cannot schedule automatic work.

The applier is the only skill writer. Existing targets use host-global bindings; new targets use one explicit creation root and `must-not-exist`. Every filesystem effect is immediately preceded and followed by root/epoch, lease-generation, path containment, no-symlink, file-identity, hash, ownership/mode, and transaction proof. Existing replacement uses a same-directory exclusive temp, fsync, atomic rename, and readback. New publication uses a complete verified temp plus create-exclusive hard link. Undo restores only exact transaction-owned bytes.

## TUI And Protocol

The native UX renders exactly Home, Recommendations, Activity, and Settings from the persistent sidebar. Settings exposes one Automatic recommendations switch, retained data permissions, project Include/Exclude, Emergency Stop, budgets/retention, explicit creation-root policy, and maintenance. It has no Manual/Auto/on-demand, project mode, Pause, scan, or passive consent.

The server publishes preference separately from operational readiness. Off does not hide the recommendation inbox or action-specific reasons. Operational suppression never rewrites the preference in projections.

The v0.4 settings/dashboard plane uses dashboard v3, UI operation v2, and `automatic-recommendations-control-v1`. Retained global recommendation/action and project-participation version-1 domains keep their exact names/tuples. Mixed v0.3/v0.4 peers are read-only limited. Old writable requests are rejected with migration guidance rather than reinterpreted.

The TUI remains a read-only projection consumer and may publish only strict create-exclusive decision/control/operation envelopes. The server freshly revalidates state-root/project identity, generation, domain versions, nonce, permissions, and action-specific authority before any effect. Purge-all publishes its accepted-terminal response before stopping authority and deleting its mailbox subtree.

## Privacy, Retention, Export, And Purge

Complete transcripts and raw message bodies are never stored. Project evidence remains partitioned. Only identity-free random-ID contributions/support/recommendations enter global learning state. Global validators reject project/worktree/source-domain/evidence-domain/capsule/cluster/observation/session/local-incident identities and derived hashes.

Revoking a required permission turns automation Off and performs that permission's existing deletion/invalidation transaction. It does not implicitly purge all retained data or published recommendations. Project/global/scoped purge and export retain their exact boundaries. Native export artifacts are exclusive, private, bounded, expiring, and never auto-opened.

Deterministic tests, packed-consumer evidence, live-host smoke, and independent human UI acceptance remain distinct evidence classes.
