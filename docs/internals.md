# Internals

The package is a dual-target Node ESM implementation of the durable v0.3 contract with bounded v0.2 compatibility input:

```text
observe -> persist -> correlate -> synthesize -> validate -> notify | apply
```

Project analysis modes are Manual and Auto. The retired `yolo` command and control request are refused, a stored v0.2 `yolo` value normalizes to Auto, and no mode grants unattended write authority; every Apply and Undo requires an explicit operator decision.

This file describes the implemented architecture and its compatibility seams. Deterministic tests cover the native target, projection store, strict mailbox protocol, and server integration without external provider calls. The isolated live smoke proves target loading, durable server integration, stable lifecycle hooks, and filesystem mailbox behavior; its production command-route check uses a loopback mock provider because OpenCode 1.18.3 continues the configured model turn after `command.execute.before`. Exact-host interactive rendering remains a separate operator evidence gate.

## Dual Targets

- `self-evolve.js` is the headless-safe server entry at `.`. It default-exports only `SelfEvolvePlugin`, imports no TUI target or `@opentui/*` runtime, owns durable writes, and exposes commands/events.
- `self-evolve-tui.tsx` is the typechecked authoring source. A repository-owned Bun step emits byte-stable `self-evolve-tui.generated.js`, the public native target exported at `./tui`; it keeps host-owned runtimes external and is generated before pack, never by consumer installation. Its default export has `{ id: "mcrescenzo.self-evolve", tui }` `TuiPluginModule` shape and implements the persistent sidebar entry point plus the four-section Home, Recommendations, Activity, and Settings control center. The target-exclusive `self-evolve-tui.js` helper owns host registration and lifecycle wiring; it is not a standalone TUI registration. None of this TUI graph is reachable from the server root.
- `self-evolve-tui-store.js` owns one reference-counted reactive projection runtime per canonical state-root/project pair. Full validated rereads are authoritative; filesystem watches are only latency hints, a bounded poller is the fallback, and owner/path generations prevent disposed or replaced TUI instances from publishing late updates. Decision, control, and operation submissions always re-read the current projection before publishing.
- Shared modules are pure server-side ESM helpers and import neither package target.

The package checker enforces the exact public manifest and approved optional-peer contract, recompiles the generated target twice with OpenTUI's supported Solid transform, rejects stale or non-deterministic bytes, legacy JSX-runtime output, and bundled host runtimes, then installs the tarball into a fresh peerless consumer and imports the root and explicit server exports. The separate packed-TUI matrix installs aligned OpenCode/TUI peers and loads and reactively renders `./tui` through Bun at exact 1.18.3, exact 1.18.4, and the dynamically resolved latest common stable 1.18.x patch. It covers OpenTUI 0.4.5 and 0.5.0 and requires npm to reject 0.6.x with a peer diagnostic.

The cross-repository coexistence lane is exposed here as `npm run
test:tui-coexistence -- --workflows <candidate> ...` and delegates orchestration
to an OpenCode Workflows checkout. For each attempt, its readiness phase uses
fresh isolated homes and exactly the two product TUI plugins in both orders,
with no witness, server plugin, MCP requirement, or provider request. A
separate post-readiness witness verifies both stable IDs and command surfaces.
Failures retain only bounded sanitized terminal/process evidence; the harness
stops its process groups and never reads or writes the real OpenCode config.

External TUI configuration loads the bare package `@mcrescenzo/opencode-self-evolve`; a source checkout loads its package directory. OpenCode resolves `exports["./tui"]` for TUI configuration. A legacy `tui.json` entry that names the `/tui` subpath, `self-evolve-tui.tsx`, or `self-evolve-tui.js` must be replaced externally with the package root and OpenCode restarted; the plugin never mutates host configuration. During rolling upgrades, the v1 offer and core index retain the Release A capability vocabulary. A new TUI labels missing Release B data limited; an old TUI reads the unchanged core and ignores the additive dashboard. Neither pair gains a new request shape or authority. The aligned pair adds the four-section native control center while retained headless commands and inbox behavior provide the compatibility path.

## Autonomy Modules

1. `self-evolve-schemas.js` defines immutable records, settings, modes, budgets, decisions, transitions, and authority evaluation.
2. `self-evolve-store.js` owns versioned project-partitioned JSONL state, atomic records, leases, CAS, retention, and corruption handling.
3. `self-evolve-observation.js` extracts deterministic receipts, forms bounded structured observations, and correlates independent incidents.
4. `self-evolve-inventory.js` discovers skill targets, canonicalizes allowlists, hashes content, rejects symlinks/unsafe paths, and enforces growth/canary checks.
5. `self-evolve-privacy.js` enforces project partitions, consent, redaction, quotas, retention, export, and purge.
6. `self-evolve-synthesis.js` runs hidden deny-all-tools synthesizer and critic sessions with strict schemas and current-content hash binding.
7. `self-evolve-applier.js` is the sole skill writer: leased, hash-bound, allowlisted, atomic, audited, readback-verified, and rollback guarded.
8. `self-evolve-commands.js` parses and executes deterministic mode, consent, inbox, decision, export, purge, and kill-switch controls.
9. `self-evolve-pipeline.js` composes observe, correlate, synthesize, critic, notify, approval, application, and rollback stages.
10. `self-evolve-scheduler.js` debounces idle events, enforces durable leases/budgets/quiet periods, rejects stale epochs, and keeps event handling non-blocking.
11. `self-evolve-integration.js` resolves effective authority, coordinates scheduler/pipeline/TUI, boots recovery, and shuts resources down.
12. `self-evolve-state-root.js` implements canonical dual-target root precedence, bounded SDK resolution, and root identities.
13. `self-evolve-ui-protocol.js` defines the strict versioned server/TUI projection, grant, request, response, and operation schemas.
14. `self-evolve-projection.js` publishes bounded server-authored review and control projections with target-derived generations.
15. `self-evolve-export.js` streams short-lived private export artifacts with exclusive creation and fixed quotas.
16. `self-evolve-tui.generated.js` is the public native target built from `self-evolve-tui.tsx`; `self-evolve-tui.js` and `self-evolve-tui-store.js` provide target-exclusive lifecycle and reactive-store support.
17. `self-evolve-lock.js` implements the shared synchronous cross-process mutation lock used by stores and mailbox publishers.
18. `self-evolve-bridge.js` implements the filesystem decision, control, operation, projection, and runtime-report protocol between server and TUI processes.
19. `self-evolve-client.js` provides the bounded shared OpenCode SDK client adapter and compatibility fallbacks.
20. `self-evolve-core.js` contains legacy v0.1 pure analyzer helpers also reused by the durable pipeline.

## Hooks And Boot

The server always registers `config`, `command.execute.before`, `dispose`, and exactly one durable lifecycle `event` hook. The config hook installs the hidden compatibility analyzer agent. Durable autonomy is the default; only `durableAutonomy: false` selects the legacy path. The factory returns the stable hook shape before host calls begin. One timer then runs a single startup state machine: bounded host-version resolution, root resolution/validation, integration creation, boot, and orphan recovery. Version resolution prefers `client.global.health()`. A missing method or recognized SDK transport/capability error uses exactly `/global/health` from the validated origin of official `ctx.serverUrl`; authentication and other authoritative SDK failures do not fall back, and an SDK timeout does not overlap the still-running call with another request. Transient transport errors and cancellable fallback timeouts retry with exponential backoff inside one fixed five-second window; invalid official inputs and authoritative health/version failures do not retry.

If both server-side global-health paths are unavailable in an embedded TUI, startup may read the package TUI target's `tui-host-health.json`. The TUI copies only official `api.app.version` into an exact-schema `0600` report bound to project, canonical root, same-account live publisher PID, random generation nonce, and a maximum 60-second lifetime; it refreshes every 15 seconds and conditionally revokes its own generation on disposal. The report, state-root boundary, and bridge ancestors must match the server's effective UID, the report must remain exactly `0600`, and neither the state root nor bridge ancestors may be group/other writable. `EPERM` or unavailable effective-UID validation fails this relay closed. The server checks the report only after global health is unavailable and still requires official root validation before store boot. Stable build metadata is accepted; prerelease, unsafe numeric, malformed, older, and 2.x versions fail closed. After exhausted startup, only the first later `/self-evolve` command serializes one fresh bounded version, root-validation, integration, and boot run. Concurrent commands share that attempt, failure remains authority-free and latched, and success atomically installs the recovered runtime before dispatching the initiating command. A module-level in-memory coordinator keyed by official host identity, project/root identity, and authority-narrowing options shares initial and late runtimes across duplicate factory hooks, deduplicates the same command/event input object, and closes the integration only after the last matching factory disposes. Different host origins, client identities, or narrowing options never share. Recovery cancellation is coordinator-owned: disposing one factory leaves shared work alive for remaining users, while final disposal interrupts and settles it. Failed health text includes only bounded categories, never raw SDK/fetch error messages. The resolved version is passed unchanged into boot, and user options cannot widen it.

Root precedence is explicit option, synchronous official host field, official path SDK, then environment only when official APIs are absent. Because OpenCode 1.18.3 exposes no documented synchronous server state field and `client.path.get()` can self-block project initialization, a standard XDG/HOME root is provisional after compatibility succeeds. A timer scheduled before return performs the bounded path call only after the factory returns. Exact match opens the store and runs boot recovery before any event or command gains authority; timeout, unavailable API, or mismatch leaves the stable event hook inert. No root is copied, merged, or migrated. The same post-start phase then retries host-session listing with bounded backoff, interrupts active and deletes active or terminal hidden sessions only when a matching dead durable owner proves self-evolve ownership, caches health, and is cancelled and awaited by disposal.

The scheduler and pipeline keep raw host session IDs only in ephemeral call state. Durable cursors and scheduler audits use a domain-separated SHA-256 session-lineage hash. A cursor stores the hash of the last observed host message ID, or a deterministic hash of the bounded legacy message shape when no ID exists. The pipeline locates the prior cursor with `lastIndexOf` and observes only the unseen suffix. A prior cursor missing from the current 120-message window is an audited gap: the cursor advances, but the unknown overlap produces no receipt, observation, or synthesis.

The durable lifecycle `event` hook is always present, including configured Manual and preboot validation. Before validated boot it reads no integration or durable state. In Manual it reads only fresh configured/operational settings, then returns before lineage hydration, session/message access, provider calls, durable observation, contribution, or scheduler admission. Passive `chat.message` is never registered. Commands likewise report `startup-validation-pending`.

The server entrypoint and integration independently admit only `session.idle`, `session.status`, and `session.compacted` to durable event routing. High-frequency message text, reasoning, and tool deltas return before runtime lookup, settings, records, mailbox, scheduler, bridge, audit, lock, or timer work. Every admitted event reads fresh project analysis and operational suppressors; Manual/Auto, pause, exclusion, kill-switch, corruption, host, and breaker changes therefore take effect on the next event without restart. The scheduled cycle rereads settings at work admission. Mailbox consumption is boot/timer/command/control driven rather than event driven, with one active pass and at most one pending rerun.

`dispose` clears the module-level legacy registry and asynchronously shuts down the integration, scheduler, applier, synthesis timers, audit buffers, and store.

## Hidden Analysis

The config hook collision-safely registers `mcrescenzo.self-evolve.analyzer`, `mcrescenzo.self-evolve.synthesizer`, and `mcrescenzo.self-evolve.critic` through the host agent config contract as hidden primary agents with temperature 0, one step, fixed prompts, and deny-all tool permissions. Session creation carries only supported lifecycle fields. Registration is checked before creation and reasserted with durable session ownership at the synchronous pre-prompt boundary. A missing, unsupported, collided, or replaced definition fails closed. At that same boundary, the OpenCode 1.18.3 `chat.params` hook claims only the matching canonical synthesizer/critic session and agent with the freshly read per-call `tokensPerSynthesis`; the critic parser uses that exact critic value rather than the synthesizer value. All user, analyzer, foreign, or mismatched traffic is untouched, and deterministic response byte/field bounds remain a second guard. The observer is deterministic and makes no model call. Inputs are typed evidence, inventory, bounded optional excerpts, and current skill content; model output cannot select scope, consent, retention, budgets, or apply authority. `session.delete` is mandatory: every prompt path best-effort interrupts and then deletes the owned child before provider output can return. Delete failure retains the durable owner and fails closed; late creation after timeout uses the same ownership/delete sequence.

For one release, orphan recovery and durable host-owner validation also recognize the former `self-evolve-analyzer`, `self-evolve-synthesizer`, and `self-evolve-critic` names, and transcript self-detection recognizes the former `self-evolve-plugin` source marker. New sessions and output use only the canonical `mcrescenzo.self-evolve` namespace. A later release retires those aliases after existing owner records and in-flight sessions have aged out; it also removes the bounded legacy TUI KV read fallback.

Passive Auto work does not charge a provider call when the scheduler starts a cycle. After deterministic preflight, each hidden synthesizer or critic call independently requests one slot immediately before dispatch. The scheduler serializes the fresh-settings check, rolling-hour durable count, and reservation write with a project-scoped process-aware lease, then verifies the durable `scheduler-budget` / `passive` audit before releasing the lease. Denial, lease contention, settings/read/write uncertainty, failed readback, cancellation before the next call, and every deterministic no-call path charge no slot for that call. With one slot remaining, synthesis can run but critic dispatch fails closed. Manual command scans never receive this reservation capability and do not consume the passive budget. `synthesisPerDay`, quiet hours, episode leases, failure backoff, and the circuit breaker remain separate scheduler controls.

The scheduler also owns normal work-promise settlement. Fulfillment, rejection, a synchronous enqueue throw, and an early authority downgrade all converge on one exact `(sessionID, leaseNonce)` ownership check before lease release, failure/backoff/breaker accounting, or continuation scheduling. Integration tracks only local pipeline cleanup and may request an early downgrade settlement; a late duplicate or an older lease result has no effect on current work.

After deterministic preflight, synthesis acquires a deterministic project/cluster/target process lease before persisting one strict `synthesis-attempt` admission with a random domain-separated outcome ID, deterministic proposal ID, project/cluster/target binding, admission time, and state `admitted`. No prompt or content is stored, and failure to acquire or persist prevents the provider call. The lease remains owned through provider output, `critic-pending`, critic transition, typed content persistence, and the terminal `synthesis-outcome` audit. Boot defers a live owner without writing an outcome or changing the proposal; a dead owner is reclaimed before the prior recovery rules run. Replaying boot is idempotent and never calls the provider. Terminal cluster records no longer suppress later synthesis; ordinary failure backoff still applies.

## Decision CAS And Mailbox

TUI and headless decisions carry:

```text
(proposalID, targetHash, proposedContentHash, decisionVersion,
 actor, timestamp, nonce, priorState, newState)
```

The store applies compare-and-swap against `priorState` as one recoverable transaction. Under the existing mutation lock it persists `decision-transaction.json`, binding the project, prior proposal envelope ID, exact next proposal and decision envelopes, and whether terminal proposal-content compaction is required. It appends both sides idempotently, compacts terminal content, then removes the intent. Boot and ordinary reads recover every partial position without duplicate records or terminal content exposure. Malformed, newer, or conflicting intents are quarantined and fail closed. A successful transition increments the decision version and burns the nonce. Stale state, target/content hash mismatch, duplicate nonce, cross-project scope, or invalid transition fails closed. Every Apply and Undo requires an exact per-change approval, including in headless operation; no mode can synthesize one. Rollback is valid only while the current disk hash equals the recorded plugin-applied hash.

The v0.3 global path uses the deeper `createGlobalDecisionDomain(...).decide({ action, decision })` interface in `self-evolve-applier.js`; callers never pass project Manual/Auto mode. The module acquires `globalTargetLeaseKey(rootId, relativePath)`, freshly resolves the approved catalog, asks the store to consume the exact operator edge, and exclusively owns every skill filesystem mutation. The store journals identity-free decisions, apply intents, sensitive snapshots, audits, and idempotent outcomes under the global state tree. A process crash can therefore resume from the exact intent stage and disk hash without replaying a provider or operator edge. Existing skills use temp/fsync/rename/readback; new skills use temp/fsync/create-exclusive hard-link publication/readback. Undo requires the recorded applied hash, restores exact snapshot bytes for an existing skill, and removes only an exact plugin-created new skill and an empty direct directory.

The separate TUI process is read-only for settings and project records. It writes create-exclusive `0600` envelopes only to separate decision, control, and operation request namespaces, plus the replaceable short-lived host-version runtime report described above. Decision envelopes retain the proposal/hash/version/state tuple and may carry capability-gated structured rejection feedback that is audit-only. Control envelopes retain compatibility actions for the installation default, consent, repository exclusion, and collection suggestions; legacy repository-mode control is inert. Native project `inherit|manual|auto`, authoritative global-root replacement, and the other operations use exact operation schemas for snooze, rollback, pause/resume, kill switch, scoped purge, sensitive export, accepted-terminal purge-all, and bootstrap retry. Root replacement is dashboard-v2-only, settings-version-bound, and transactionally revalidates canonical identity, symlinks, project-root exclusion, capabilities, primary creation authority, and the complete direct-child catalog. Presentation-only acknowledgements stay under project-keyed host KV entries bound to scope, exact outcome version, and authoritative audit/detail hashes; they never mutate server records. Every request binds a strict server-authored projection or grant, canonical state-root identity, generation/domain versions, actor, timestamp, request ID, project, and one-use nonce. The TUI validates projected root identity and freshness before reads and submission. Global Apply, Reject, and Undo additionally consume one freshly composed project snapshot containing the aligned projection, control state, and current TUI health report. The server consumes all request namespaces under the mailbox lease, freshly revalidates authority and target-derived generations, performs the store/integration operation, burns the nonce, and publishes a bounded response. Completion audits bind the complete normalized envelope with domain-separated request digests, nonce hash, status, and bounded reason. If response publication fails after completion, an identical queued envelope reconstructs that outcome without rerunning side effects; altered or nonce-reusing envelopes fail closed.

The server continues to publish the unchanged bounded core review index. Independently discovered additive `dashboard-v2` and `dashboard-v1` compatibility artifacts derive readiness, actual usage, semantic activity, diagnostics, and closed Release B feature capabilities from existing records without changing durable schemas or the Release A offer. Current readers prefer strict v2 and fall back to permissive v1; older dashboard readers continue to discover only v1. The native palette command `mcrescenzo.self-evolve.control-center` and persistent sidebar render exactly Home, Recommendations, Activity, and Settings. Sidebar, header, and Home consume one pure operational model; the sidebar deep-links into the appropriate section, and the control-center mode restores the exact prior route on Escape. Activity maps only allowlisted semantic events and never exposes raw audit detail or a raw-log viewer. The normal path emits no toast, attention notification, auto-opened dialog, or state-dependent review dialog. No undocumented `api.client.selfEvolve`, arbitrary command string, direct record append, or session prompt injection is part of the contract. Headless commands, including the source-session manual scan fallback, invoke server integration directly rather than writing mailbox files.

Mailbox paths share one canonical state-root boundary. Each existing component through the project and namespace is `lstat`/`realpath` checked for containment immediately around operations; final reads use `O_NOFOLLOW` and inode/link-count checks. Request/response publication is restrictive, same-directory, and create-exclusive. Symlink ancestors/finals, hard-link aliases, path replacement detected around open/publication, and unsupported no-follow platforms fail closed. Atomic bridge publications fsync file contents and then inode-checked parent directories after rename or link publication; after projection details and sidecars publish, their directory chain is synced bottom-up from `details/` through `generations/` and every in-bound ancestor to the state boundary before the offer and core index commit. Consumer-lock recovery and retention cleanup use the same path policy and unlink only validated in-bound entries.

## Durable State

Global settings use `<state-root>/self-evolve/global/settings.json`; each checkout/worktree uses `<state-root>/self-evolve/<projectFingerprint>/` for repository settings and records. Exact v0.3 evidence capsules are project-local objects in `evidence-capsules.jsonl`; contribution intents and links are sharded project-local JSON records. Immutable identity-free global contributions live at `global/contributions/<uuid-prefix>/<contributionId>.json`; candidates and support sets use content-addressed shards; attempts use opaque-ID shards; recommendations and canonical Base64 content chunks use separate recommendation-ID shards; short-lived identity-free global leases live under `global/leases/`. Global synthesis assembles each bounded evidence packet in memory during its locked dispatch/revalidation transaction, releases the mutation lock before hidden provider use, and persists no packet or excerpt. The injected clock is sampled independently for admission, each pre-prompt boundary, terminalization/failure, and lease release; numeric test callers remain a deterministic constant clock. Successful no-change writes candidate `no-change` before attempt `completed`, while recommendation completion writes chunks, recommendation, candidate `recommended`, then attempt `completed`; recovery recognizes both ordered crash markers without replay and rejects invalid partial artifacts consistently. Server and TUI call the same state-root and project-identity resolvers. Explicit roots must be canonical absolute paths. Official SDK results outrank and must validate a provisional environment root even when they disagree. Explicit project fingerprints are format-checked and must agree with derivable inputs. Settings are read fresh before every command, cycle, decision, apply authorization, excerpt operation, contribution publication, and global synthesis dispatch. Store settings updaters, contribution publication, and global synthesis admission perform their fresh read, validation, quota checks, and writes in one recoverable cross-process lock critical section.

Records are append-only JSONL except lifecycle compaction. Proposal bodies use strict `proposal-content` records co-located in `proposals.jsonl`; each chunk binds proposal ID, proposed hash, base64 encoding, index, and count. Readers require one complete canonical set and verify the decoded SHA-256. Active critic-pending/pending/approved/applied content survives retention; rejected/failed/superseded/rolled-back and purged proposal content is deleted immediately. Valid legacy content audits migrate to typed chunks and all legacy body audits are removed. Cross-project global-skill contributions are separately dual-consented, strict immutable records under `global/contributions/`, with private project-local intents and links for recovery, retention, and project purge. Store writes use same-directory temporary files and rename, while contribution and lease publication use create-exclusive files. Existing skill replacement uses rename. New-skill publication validates the full same-directory temp and uses an atomic create-exclusive hard link followed by temp unlink; unsupported filesystems fail closed rather than using an overwrite-capable fallback. Recovery recognizes a complete published hash or removes only a same-directory, name-bound, hash-proven plugin temp. Complete transcripts, raw message bodies, and raw host session/message IDs are never stored. Observations keep incident identity separate from their exact SHA-256 session-lineage hash; eligibility counts a lineage once across multiple incidents, and missing legacy lineage collapses to one unknown lineage. Retention defaults are 30 days for observations and observation-like evidence; 90 days for proposals, decisions, audits, rollback/intervention/circuit records, and snapshots; a fixed 24 hours for decision/control/operation bridge envelopes; at most 60 seconds for the operational TUI report; and an explicit 30-day expiry assigned to immutable contributions. Native export artifacts have their own short expiry and are purged with their project. The sole non-age audit exception is the exact content-free scheduler diagnostic `session-status`/`busy`: it is no longer written and any existing backlog is drained, while retry, compaction, cleanup, decision, apply, rollback, nonce, and CAS records keep normal retention. Startup recovery and daily sweeps enforce retention.

Legacy aggregate JSONL and indexes are compatibility input only. New publication is one deep store operation: dual-consent and complete project/global quota preflight, random-ID local intent, create-exclusive immutable global write and readback, create-exclusive local link, then committed intent. Boot scans every project partition and resumes the exact state; retries reuse the local allocation. Provider work starts only after any global lease acquisition returns and the mutation lock is released.

Quota accounting recursively sums every regular file in the project partition and project bridge directory, rejects symlinks/special files, substitutes pending replacement sizes, and compares once against `storageQuotaMiB` under the shared mutation lock. Contribution preflight adds a fixed 16,384-file project ceiling. Global accounting similarly combines `global/` and `bridge/global/` under one fixed 64 MiB and 16,384-file cap, substitutes each side's planned replacements, preserves durable lifecycle reservations, and excludes project sidecars from the global total. Decision/control/operation request publishers use the shared lock, a 64-pending-request ceiling, a `min(512 KiB, project quota / 8)` mailbox sub-budget, maximum-response and absent-control-state reservation, and a store-capacity reserve. Snapshot creation goes through the store for the same reason. Native exports have a separate fixed temporary quota. A safety-mandatory settings audit append is capped at 4 KiB and is the only project-quota exception.

Project export remains scoped and labels each capsule `sensitive-evidence-capsule`. Headless state-root `export all` returns global settings/aggregates, contributions, candidates, support, synthesis attempts, recommendations/content, decisions, apply intents, outcomes, audits, and classified skill snapshots, plus all project settings/records/capsules/indexes, per-class bounded and classified decision/control/operation request/response metadata, classified control-state metadata, and Base64 rollback snapshots labeled sensitive. It excludes capsules from the global member, raw quarantine, and operational files such as `tui-host-health.json`. Native export streams an equivalent bounded JSON artifact into a private `0700` export directory using exclusive `0600` creation, a 64 MiB artifact limit, a 128 MiB temporary quota, one active job, an expiry, and SHA-256/size/path metadata; it never auto-opens the file. Purge-all first publishes an accepted-terminal response, stops timers and authority, and then removes the subtree after a bounded handoff delay; boot recovery consumes the terminal intent after a crash. No settings read, retention, mailbox, event, later command, or disposal path can recreate the subtree before restart.

Legacy rollout metrics scan only strict `synthesis-outcome` audits in this store, validate their producer and full bounded shape, enforce current-project binding, and deduplicate by outcome ID. Accepted and valid no-change outcomes are successes; critic rejection and failure are failures. These metrics remain compatibility diagnostics and never grant write authority.

## Validation

Run `npm test`, `npm run check`, and `npm run pack:check` as the baseline. The heavier deterministic lanes are `npm run test:tui-matrix` for packed peer-version compatibility and `npm run bench:perf` for bounded performance budgets. `npm run operator:evidence` drives the isolated operator fixture against the packed production TUI target; the current v0.3 result is recorded in `docs/v03-operator-evidence.md` and does not replace independent human acceptance. `npm run smoke:live` is an optional no-external-token local host smoke: its fresh direct-registration child executes `/self-evolve health` through the production session-command route with a loopback mock provider, then proves process and temporary-state cleanup. Restart OpenCode after plugin, TUI registration, startup-option, or skill changes; Manual/Auto settings take effect on the next eligible lifecycle event.
